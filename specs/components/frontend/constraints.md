# 制約

## API 依存

- フロントエンドは相対パス `/api` を使い、nginx または開発時プロキシ経由でバックエンドに到達する。
- コンテナ内 nginx は相対 redirect を返し、外部 reverse proxy が公開する scheme、host、port を画面 reload 後も維持する。
- リクエストエラーは `extractErrorMessage()` で正規化する。
- `useBookmarkApi()` は共通の fetch 基盤として使われ、全ページが同じ `/api` 起点を参照する。

## UI 構造

- アプリは default レイアウトで共通のダッシュボードシェルを使う。
- フォルダとタグの子ナビゲーションはサイドバーカタログから生成されるため、古いカタログ状態はツリー表示に影響する。
- RSS フィードと custom news site の子ナビゲーションもサイドバーカタログから生成される。
- `BookmarkCard` は一覧表示側で補完された `folder_name` を前提にする。

## 状態とデータ

- ブックマークの作成・編集フォームは、フォルダとタグの関連付けを任意で受け付ける。
- ブックマーク一覧ページは、サーバー側フィルタに加えてクライアント側検索文字列も扱う。
- ブックマーク一覧のページ番号は、サーバー応答の総ページ数に収まるよう URL と表示状態を同期する。
- お気に入り一覧は API のページング応答を使い、更新後に件数と現在ページを再同期する。
- RSS フィード一覧は API のページング応答に現在ページを同期し、最後のページが削除されても有効なページを表示する。
- フォルダ/タグ詳細ページは、親エンティティと関連ブックマークを両方読み込み、関連一覧のページ番号・総件数・総ページ数を API 応答に同期する。
- RSS フィード詳細ページは親フィードと関連記事を両方読み込む。
- custom news site 詳細ページは親 site と scraped article を両方読み込む。
- お気に入り一覧は bookmark の `is_favorite` を基準に表示する。

## UX ルール

- 破壊的操作は確認モーダルを必須とする。
- 保存フローは成功・失敗ともに toast で通知する。
- API 接続確認の toast は共通レイアウトの初回ロードで表示する。
- API 接続失敗中は共通レイアウトに永続的なエラー表示と再試行操作を表示する。
- API 接続が復旧した場合はサイドバーカタログを強制再取得する。
- RSS 一覧画面は RSS と custom news site の管理、webhook 通知、定期実行設定を持つ。
- LLM 未設定時は custom news site 登録を無効化し、設定画面への導線を表示する。
- custom news site 登録中は HTML 解析と抽出テストの完了まで保存中状態を表示する。
- custom news site の登録・URL 更新失敗は toast だけでなく editor modal 内の error alert に保持し、失敗段階と reference ID を確認できるようにする。
- custom news site 更新時のLLM再解析は任意で、モーダルを開くたびに未選択へ戻す。
- 設定画面はテーマ、webhook、LLM 接続の管理を提供し、LLM API key の保存値は再表示しない。
- API が利用できない場合でもカタログ読込のPromise rejectionを画面外へ漏らさず、UIを維持してエラー状態を表示する。

## スタイリング

- アプリは Nuxt UI のダッシュボードコンポーネントと共通の `font-sans` テーマを使う。
- レイアウトはレスポンシブで、モバイルとデスクトップの両方で動作する必要がある。
- サイドバー幅の固定や、デスクトップ専用の操作前提に依存しない。

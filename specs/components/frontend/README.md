# Frontend 仕様

Nuxt 4 SPA は RSS 専用 UI を提供する。

- `/` はサマリーとアクセス時点から直近24時間の通常RSS・カスタムRSS記事を表示し、フィードに設定済みの画像アイコンがある場合は記事ごとの種別アイコンの代わりに表示する。
- `/feeds` は通常RSSの一覧、作成・更新・削除、手動取得を提供する。手動取得は自動通知設定を上書きし、有効な送信先があれば未通知記事も送る。
- 通常RSSとカスタムRSSは、PNG・JPEG・GIF・WebP（最大1 MB）のアップロードまたは外部画像URLで任意のアイコンを設定でき、一覧カードと詳細画面ヘッダーへ表示する。設定と削除は一覧・詳細の編集モーダルから行える。
- `/feeds/{id}` はフィード詳細と記事履歴を提供し、記事サマリーをプレーンテキスト化して160文字・最大3行で表示する。
- 通常RSSの記事公開日時は、RSS XMLに記載されたUTCオフセットの日時を維持して表示する。
- `/custom-feeds` はAI解析または手動CSSセレクタ設定で作るカスタムRSSの一覧、作成・更新・削除、手動取得を提供する。作成・編集モーダルはAI setupとManual setupをタブで切り替え、手動設定では記事要素、タイトル、リンク、任意の概要・公開日時のセレクタと属性を入力し、LLMを呼ばずにライブ抽出テストして保存する。カスタムRSSは定期巡回の対象外で、取得は画面から手動で行う。モーダルは画面高を超える場合にフォーム領域を縦スクロールでき、入力項目、解析・抽出エラー、操作ボタンを確認できる。
- `/custom-feeds/{id}` はカスタムRSSの詳細と抽出済み記事を提供し、通常RSS詳細と同じリスト型レイアウト、タイトル・公開日の検索、番号付きページネーション、記事サマリーの160文字・最大3行表示を使用する。
- 通常RSSとカスタムRSSの詳細画面は、最大横幅、中央寄せ、ヘッダーカード、検索、記事一覧、公開日時、通知状態、ページネーションを共通コンポーネントで統一して描画する。
- サイドメニューは Home、通常RSS、カスタムRSS、GitHub、AI analysis data、Preferencesで構成する。通常RSSとカスタムRSSの見出しクリックは折り畳みを切り替えながら各一覧ルートへ移動し、配下から詳細画面へ直接移動できる。GitHubとAI analysis dataは各一覧へ直接遷移する。
- `/github` はRSSとは独立したGitHubリポジトリ管理画面であり、リポジトリURLの登録・削除・一括更新、リポジトリごとの通知先Webhook複数選択と、各リポジトリの最新公開リリース1件の名前、タグ、公開日時、概要、リンクを表示する。通知先未選択時は通知しない。
- `/settings` は General、Automation、Webhooks、LLM のカテゴリタブを持ち、テーマ、通常RSSの定期取得、定期実行時の全体通知、Webhook、LLM接続設定を提供する。Webhooksタブでは1回のフィード実行で通知する最新記事数を1〜100件で設定でき、既定値は20件とする。同じバックログ内の古い記事は後続実行で通知しない。Automationの設定は手動取得を抑止しない。LLMタブではデフォルトOFFのAI記事解析バッチ、1回の記事数、日次トークン上限、対象期間を設定でき、記事情報の送信とトークン消費に関する注意を表示する。
- LLM設定のArticle analysis batchから、確認モーダルを経て保存済み解析結果を全件クリアできる。この操作はAI analysis data画面には置かず、日次トークン使用量を維持したまま次回実行での再解析を可能にする。解析中は実行できない。
- `/ai-data` は保存済みAI記事解析データを表示し、記事・配信元・要約の検索、ソース種別と成功状態の絞り込み、ページングを提供する。要約、要点、トピック、キーワード、固有表現、モデル、プロンプト版、トークン数、試行回数、失敗内容を確認でき、LLM設定タブから遷移できる。失敗結果がある場合は件数付きの削除ボタンを表示し、確認モーダルを経て失敗結果だけを削除する。成功結果とトークン使用履歴は残し、解析中は削除できない。`Run analysis now` は定期解析がOFFでも同じ制限で解析を実行する。画面はAPIの実行状態を3秒間隔で取得し、手動または定期解析中はloading表示と `Analysis running` ラベルでボタンを無効化し、Nuxt UI Alertに加えてProgressで処理済み/対象件数と割合、現在の記事タイトル、成功・失敗・スキップ件数、当日トークン使用量を表示する。実行中は `Stop analysis` から停止要求を送信でき、現在の記事の完了を待つ間は停止中表示にする。完了後は進捗表示を自動で消して結果件数を通知し、一覧を再読込する。エラーで停止した場合はAPIの理由をエラーAlertで表示し、次の実行開始時または利用者のDismiss操作で消去する。
- 全画面の右下に `Ask AI` ボタンを固定表示し、クリックすると保存済み記事の横断検索・要約チャット用モーダルを開く。直近4往復と直前回答の出典を次の質問へ渡し、`S9の内容` のような継続質問に対応する。履歴はモーダル状態だけに保持し、サーバーへ永続保存しない。LLMの回答は読み取り専用のNuxt UI EditorでMarkdown表示し、回答が実際に引用した通常RSS・カスタムRSSの記事だけを参照番号付きリンクとして表示する。回答はNDJSONストリームから逐次反映し、Nuxt UIの `ChatMessages` による自動スクロールと `ChatPromptSubmit` のsubmitted・streaming・error状態を使用する。submitted・streaming中の送信ボタンは、停止操作を維持したまま回転する `loader-circle` を表示する。
- 一覧と設定画面は宣伝的なヒーローやキャッチコピーを置かず、操作対象を先頭に表示する。
- Home、Custom RSS、GitHubの一覧は375px幅でも横スクロールを発生させず、長い記事名・URL・リポジトリ名・リリース本文をカード内で折り返す。
- 非同期処理を実行する `UButton` は `loading-icon="i-lucide-loader-circle"` を明示し、処理中アイコンを画面間で統一する。アイコン操作と更新操作は既存の共通ボタンを使用する。
- E2Eヘルパーは実行ごとに空きポートと一時SQLite DBを確保し、並行・残留プロセスとの競合を避ける。明示した `FRONTEND_PORT`、`API_PORT`、`DATABASE_URL` はそのまま使用する。
- サイドバーには Home、RSS feeds、Custom RSS、GitHub、AI analysis data、Preferencesを表示する。
- 旧 `/rss` と `/rss/{id}` ルートは提供しない。
- API 呼び出しは `useApi` と `/api` reverse proxy を通す。
- 保存、削除、取得、再読込、通知切替などの非同期ボタンは、処理中にNuxt UIの `loading` 状態とLucideの `loader-circle` アイコンを表示して再実行を防ぐ。
- 手動AI解析はPOSTリクエスト中とサーバーの実行状態を別に保持し、ステータスポーリングが開始直後に未実行を返してもリクエスト完了前にloading表示と無効化を解除しない。

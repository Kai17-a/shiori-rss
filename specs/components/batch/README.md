# Batch 仕様

Rust batch は RSS / Atom フィードだけを定期巡回し、通常RSSとカスタムRSSの保存済み記事をAI事前解析する。カスタムRSSの取得はAPIの手動実行が担当する。

- SQLite の `app_settings`、`rss_feeds`、`rss_feed_webhooks`、`webhook_endpoints`、通常RSS・カスタムRSSの記事、AI解析結果・使用量テーブルを読む。
- 通常RSSの定期実行が無効ならRSS巡回を行わない。定期通知が無効でも、定期実行が有効なら取得と未通知記事の保存は行う。
- 取得と送信はタイムアウトを設け、Webhook の 429 / 5xx を最大3回試行する。
- 未通知記事をフィードごとの選択先へ送り、選択がなければ有効な全送信先へ送る。
- 1回の定期実行では未通知記事を公開日時の新しい順に並べ、フィードごとに `webhook_max_articles_per_run`（既定20件、1〜100件）まで通知する。送信成功後は同じバックログの古い記事も処理済みにして後続実行では送らず、送信失敗時は未通知のまま最新記事から再試行する。
- 通常RSSにアイコンURLがある場合、Discord Webhookの `avatar_url` に設定する。SlackとTeamsには通知アイコンを追加しない。
- Microsoft Teams通知の記事リンクは、Adaptive CardのTextBlock内でMarkdownの `- [title](url)` リストとして送る。
- Webhookがなくても記事を未通知として記録し、1件以上の送信成功後だけ同じバックログを処理済みに更新する。
- RSS記事の公開日時はXMLの `pubDate` / `published` を優先し、元のUTCオフセットを保ったISO 8601形式で保存する。公開日時がないAtom記事では `updated` を使用する。
- AI記事解析はデフォルトOFFとし、有効時だけRSS巡回処理の後に通常RSS・カスタムRSSの保存済みタイトルとサマリーを設定済みLLMへ送る。通常RSSの定期実行が無効でもAI解析設定は独立して評価する。
- 新規・内容変更・モデル変更・プロンプト変更・前回失敗の記事を対象に、1回の記事数、対象期間、日次トークン上限を適用する。
- 成功時はAI要約、要点、トピック、キーワード、固有表現を保存し、呼び出しごとの実使用量または推定使用量を記録する。
- `--article-analysis-only` はRSS巡回を行わず、定期解析の有効設定を無視してAI記事解析だけを手動実行し、結果件数をJSONで標準出力へ返す。件数・期間・日次トークン上限は定期実行と共通とする。
- 定期実行と手動実行はSQLite上の開始時刻・プロセスID付き有効期限ロックを共有し、同時に複数のAI解析を開始しない。所有プロセスの終了時に自身のロックを削除し、APIは異常終了で残った孤立ロックを検出して除去できる。
- AI解析は開始、記事単位の処理・使用トークン、失敗、最終件数を標準エラーへ出力し、手動実行時はAPIログへリアルタイム転送される。

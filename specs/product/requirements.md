# RSS アプリ要件定義

## 目的

本システムは、RSS / Atom フィードとLLMで生成するカスタムRSSの購読、記事履歴の閲覧、Webhook 通知を行う専用アプリである。ブックマーク、フォルダ、タグ、ブラウザ拡張は提供しない。

## RSS フィード管理

1. 利用者は URL、タイトル、任意の説明を指定して RSS / Atom フィードを登録できる。
2. URL は HTTP(S) かつ取得・解析可能な RSS / Atom フィードでなければならない。
3. フィード URL は重複登録できない。
4. 利用者はフィードの一覧、詳細、記事履歴を閲覧し、更新・削除できる。
5. 記事履歴はタイトル検索、公開日範囲、ページングに対応する。
6. 通常RSSとカスタムRSSには、画像アップロードまたは外部画像URLで一覧・通知用アイコンを設定できる。

## カスタムRSS

1. 利用者は記事一覧ページのURLを登録し、設定済みLLMに記事要素のCSSセレクタを生成させられる。
2. 利用者は登録・編集モーダルのタブでAI設定と手動設定を選択できる。手動設定では記事要素、タイトル、リンクと、任意の概要・公開日時のCSSセレクタおよび属性を指定でき、LLM接続を必要としない。
3. AI設定の登録・再解析時と手動設定の保存時は、対象ページからタイトルとURLを1件以上抽出できることを検証する。
4. 利用者はカスタムRSSの一覧、詳細、記事履歴を閲覧し、更新・削除・手動取得できる。
5. カスタムRSSの記事もWebhookの有無に関係なく保存し、`webhook_notified` で後続通知の状態を保持する。

## 実行と通知

1. 利用者は通常RSSとカスタムRSSを手動実行できる。手動実行は自動通知の全体設定とフィード別設定を上書きし、有効な送信先があれば未通知記事を送信する。
2. 定期実行を有効にすると、batch が設定された cron スケジュールで通常RSSを巡回する。カスタムRSSは定期巡回せず、画面から手動実行する。
3. Webhookの登録有無や通知設定に関係なく、取得した新着記事を記事履歴へ記録する。
4. 記事は `webhook_notified` で通知状態を保持し、未通知記事を後続の手動実行または定期実行で通知する。
5. 1件以上の送信先で通知に成功した場合だけ、対象記事を通知済みに更新する。
6. フィードごとに通知先を選択でき、未選択時は有効な全 Webhook を対象にする。
7. Discord、Slack、Microsoft Teams の Webhook を複数登録・疎通確認・有効化・削除できる。
8. 通知に記事概要を含めるかを全体設定で切り替えられる。
9. アイコン変更を受け付けるDiscord Webhookではフィードごとのアイコンを通知アイコンとして使用する。
10. 利用者は1回のフィード実行でWebhook通知する記事数を1〜100件で設定できる。通知時点の未通知記事を公開日時の新しい順に選び、最新の上限件数だけを送る。同じバックログ内で上限から外れた古い記事は次回実行で送らない。通知に失敗した場合は処理済みにせず、次回に最新記事から再試行する。

## UI

1. `/` はリダイレクトせず、通常フィード数、カスタムRSS数、直近24時間の記事数、Webhook未通知数のサマリーと、アクセス時点から24時間以内の記事を表示する。
2. ナビゲーションは Home、折り畳み可能な RSS feeds、折り畳み可能な Custom RSS、GitHub、AI analysis data、Preferencesを表示する。フィード種別の見出しクリックで折り畳みを切り替え、対応する一覧ルートへ移動する。GitHubとAI analysis dataは各一覧へ直接遷移する。
3. `/feeds` で通常フィードの CRUD と手動取得を操作できる。
4. `/custom-feeds` でカスタムRSSの CRUD と手動取得を操作できる。
5. `/feeds/{id}` でフィード情報と保存済み記事を閲覧・検索できる。
6. `/custom-feeds/{id}` でカスタムRSS情報と保存済み記事を閲覧・検索できる。
7. `/settings` は General、Automation、Webhooks、LLM のカテゴリタブで設定を切り替える。
8. Automation タブで通常RSSの定期実行と、定期実行時のWebhook通知の有効・無効を管理できる。これらの設定は手動実行を抑止しない。
9. General、Webhooks、LLM タブでテーマ、通知先と1回の通知記事上限、LLM接続をそれぞれ管理できる。
10. 全画面右下の `Ask AI` から、保存済み記事を横断検索して要約を質問できる。
11. Ask AIの回答は実際に参照した記事だけを出典リンクとして表示し、検索候補に含まれただけの無関係な記事は回答本文・出典のいずれにも表示しない。
12. Ask AIの回答本文はLLMから受信した順に表示し、送信ボタンはNuxt UI Chatの状態表示と停止操作を提供する。
13. `/ai-data` でDBに保存されたAI記事解析の要約、分類メタデータ、モデル、トークン数、成功・失敗状態を検索・絞り込み・ページングして確認できる。
14. 旧 `/rss`、`/rss/{id}` ルートは提供しない。
15. 一覧と設定画面にはキャッチコピー用のヒーロー領域を設けず、主要操作を優先して表示する。

## LLM 接続

1. 利用者は Ollama、vLLM、OpenAI互換の接続先、モデル、任意のAPI keyを設定できる。
2. APIは実際のchat completionが成功した場合だけ設定を保存する。
3. 保存済みAPI keyはレスポンスへ返さず、登録済みかどうかだけを返す。
4. 利用者は保存前の疎通テスト、保存済み設定を使った再テスト、設定削除を行える。
5. 保存したLLM接続を、カスタムRSS登録時のページ構造解析とセレクタ再解析に使用する。
6. Ask AIは質問をキーワード・期間・記事種別へ構造化し、SQLite FTS5で通常RSSとカスタムRSSの記事を横断検索する。
7. 検索候補のタイトル、保存済みサマリー、利用可能な解析済みAIメタデータをLLMで関連性判定し、質問と直接関係する記事だけを回答生成へ渡して参照番号を付ける。記事本文が保存されていない場合は取得済み情報の範囲を超えて補完しない。
8. 保存済み記事のタイトルとサマリーをバッチで事前解析し、AI要約、要点、トピック、キーワード、固有表現を専用テーブルへ保存できる。この機能はデフォルトOFFとする。
9. 設定画面では、外部LLMへの記事情報送信とトークン消費に関する注意を表示し、1回の記事数、1日のトークン上限、対象期間を設定できる。
10. AI記事解析は定期バッチを有効にしなくてもAI analysis data画面から手動実行できる。手動・定期実行中はボタンと画面内Alertに加え、対象・処理済み件数と進捗率、現在の記事、成功・失敗・解析済みスキップ件数、当日トークン使用量を確認できる。完了後に成功・失敗・解析済みスキップ件数とトークン上限到達状態を確認できる。実行がエラーで停止した場合は、その理由を画面内のAlertで確認できる。
   設定画面では確認後に保存済み解析結果をクリアでき、利用量履歴を維持したまま対象記事を次回実行で再解析できる。解析中のクリアは許可しない。
11. GitHubリポジトリを一括管理し、登録した公開リポジトリごとに最新の公開リリース1件を確認できる。登録・削除・全件更新とリポジトリごとのWebhook通知先選択を画面から実行でき、定期バッチで新しい公開リリースを検出した場合は選択された有効なWebhookへ重複なく通知する。通知先未選択時は通知しない。
